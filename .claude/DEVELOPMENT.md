# Coding Style Guide

### Basic Coding Guidelines

- Written in TypeScript and Angular.
- Each template must be defined in the component "\*.ts" file using the `template` property of the `@Component` decorator.
- Each official style must be defined in the component's `index.less` file.
- Each CSS patch must be defined in the component's `patch.less` file.
- Ant Design v6 styles are generated, not written: `scripts/build/v6/components.ts` lists the components that have v6 output, and `nx run ng-zorro-antd-lib:generate-v6-styles` produces their CSS from antd. The only hand-written v6 file is the component's `style/v6/patch.css`.
- Migrating a component to v6: (1) add it to `scripts/build/v6/components.ts` with its antd component names and root class (`prefixCls`, e.g. `ant-btn`) — a preset that has no style module of its own (AutoComplete, TimePicker) registers under its host component's style module via `ANTD_STYLE_MODULE_OVERRIDES` in the same file, since that module may be imported only once by the engine; a style module with no default export (antd's `grid/style` exports only `useRowStyle` and `useColStyle`) is imported by its named hooks, listed in `STYLE_MODULE_NAMED_EXPORTS` (`scripts/build/v6/bundle-engine.ts`), since esbuild rejects a default import of it; an antd name whose style module registers more than one default-token factory goes in `MERGED_FACTORY_NAMES` (`scripts/build/v6/shims/cssinjs-utils.js`; Grid only), which merges the factories instead of throwing, and gets a recorder test in `scripts/build/v6/__tests__/registry-guard.spec.ts`; an entry whose antd names share their directory's style module (Row and Col under `grid`) is that module's owner (`ownsStyleModule` accepts `antdStyleModuleDir(name) === dir`), while a preset alias is not; (2) align host classes and templates until `scripts/build/v6/__tests__/class-coverage.spec.ts` passes with only documented permanent entries in `scripts/build/v6/class-allowlist.json` (classes that antd itself emits but its v6 CSS never styles, explained in the file's comment keys; categories include `pending-map (<dir>)` for a class owned by a component not yet mapped, removed once that component is mapped) — a nested antd component's own token block (e.g. Dropdown's inside Transfer) is foreign and dropped by `dropForeignComponentVarBlocks`, so never add the nested component's name to the entry to silence coverage; keep the default (v4) rendering intact: add v6 classes next to v4 ones, but never a v6 class that the compiled v4 CSS (`publish/ng-zorro-antd.css`, not the Less sources, which hide `&-suffix` nesting) also styles — grep the compiled CSS before adding a class; `scripts/build/v6/__tests__/v4-rule-guard.spec.ts` enforces this from `scripts/build/v6/emitted-classes-baseline.json` and fails the commit otherwise (the guard only sees classes written as complete lowercase literals in a component's sources; a template-literal or helper-built class name, e.g. `` `${prefixCls}-x` ``, `getStatusClassNames(...)`, or a class list a directive builds at runtime, is invisible to it and must be checked against the compiled v4 CSS by hand when written) — key its v6 rule onto a class or structure v4 leaves alone instead; the same spec also guards each source file: a v4-styled class that leaves the file it was emitted from in the baseline fails it, so keep v4 classes on their elements, and record a deliberate move to another file as `v4-compat (relocated: <file>)` in the directory's allowlist comment; mirror v6 rules onto ng-zorro-specific structure in `style/v6/patch.css`, and compare default-theme screenshots before and after (`capture.ts --theme default`); for popup components also capture the opened state in the default theme before and after (`capture.ts --component <dir> --theme default --opened`, which opens the trigger registered for the directory in `CLICK_TRIGGERS` or `HOVER_TRIGGERS` of `tools/v6-compare/triggers.ts`); when antd renders the component through another antd component's styles (Timeline through Steps), set `stylesThrough: { dir, from, to }` on the entry so the generator copies that mapped directory's extracted rules under this component's prefix instead of emitting the other component's classes; (3) port `style/patch.less` to `style/v6/patch.css` using `--ant-*` variables; the published `<dir>/style/v6/index.css` also carries the patches of the component's style-module host and of the mapped owners of its `renderedPrefixes` (`v6PatchDependencies` in `components.ts`), in map order, so list every mapped prefix the component renders there; (4) for components with popups, add an overlay test using `expectMotionSettled` from `ng-zorro-antd/core/testing`; (5) run `npm run v6:update-manifest` and commit `scripts/build/v6/manifest.json`, the regenerated `components/core/theme/generated/{tokens,component-roots}.ts` and the docs coverage list; (6) run `npx tsx tools/v6-compare/build-demos.ts --component <dir>`, `collect-classes.ts --component <dir>` and `capture.ts --component <dir>` with the doc site running, adding `--viewport <px>` (320 to 2560; default 900) for a responsive demo captured at several page widths (grid at 375 and 1280, saved under `out/<dir>/<theme>@<px>/`), attach `tools/v6-compare/out/index.html` screenshots to the review, and add demo pairings to `tools/v6-compare/demo-map.json`; the class-coverage audit (`class-coverage.spec.ts`) is per directory — `styledClassesFor(dir)` covers only that directory's own manifest classes plus its `v6PatchDependencies(dir)` owners' classes, not every migrated component's classes, so an allowlist entry is stale only when that narrower set actually styles it; (7) at a plan's end, run `npm run v6:update-baseline` and commit the refreshed `scripts/build/v6/emitted-classes-baseline.json` so the v4-rule guard's next plan starts from the classes this plan shipped.
- Templates must follow the structure of the associated Ant Design component. Documentation can be found [here](https://ant.design/llms.txt) and [here](https://ant.design/llms-full.txt).
- Support Server Side Rendering (SSR).
- All imports of NG-ZORRO components need to be absolute. Example:

```typescript
import { NzMentionComponent } from 'ng-zorro-antd/mention';
```

### Component Development

- All code added to a component must be covered by unit tests. For guidelines on how to write unit tests, see the [testing](./TESTING.md) file.
- New development on existing components must respect the existing structure of the component; where possible, use modern Angular features.
- New components must be developed using the latest Angular features.
- New features must be documented and include a demo. Guidelines on how to document can be found [here](./DOCUMENTATION.md).

### Renamed and v6-only inputs (Ant Design v6 parity)

- A new input takes antd 6's current prop name with the `nz` prefix. When the existing input matches a name antd deprecated, keep it as an alias: the new input is the source of truth, and the old one is a setter (or a second signal `input()`) that maps its value onto the same state through `aliasDeprecatedInput(component, oldName, newName, map)` from `ng-zorro-antd/core/util`. The helper warns once in dev mode; when both are bound, the new input wins.
- Put `/** @deprecated Use \`nzNew\` instead. This will be removed in v23.0.0. */` and the marker line `// v6-alias: nzOld -> nzNew` above the old input, and add a row to `docs/v6-migration-notes.md` (component selector, old input, new input, value mapping, removal version). `scripts/build/v6/__tests__/migration-notes.spec.ts` fails for a marker without a row.
- Every `nz*` input and output of menu, steps, timeline, splitter, flex, divider, tag, badge, tabs, pagination, progress, float-button, grid, layout, dropdown, breadcrumb, card and image has a row in both `doc/index.en-US.md` and `doc/index.zh-CN.md`. A deprecated row is struck through (`~~[nzOld]~~`) and starts with `Deprecated, use [nzNew] instead.` / `已废弃，请使用 [nzNew]。`. An input that only renders under the v6 stylesheet ends its description with `Requires the v6 stylesheet.` / `需要 v6 样式表。` and is listed in `V6_ONLY` of `input-docs-coverage.spec.ts`.
- A delivered antd prop goes into `DELIVERED` of `api-gaps-consistency.spec.ts`. Its `docs/v6-api-gaps.md` row is deleted, or rewritten when only part of it is closed.
- A v6-only feature must not throw or break layout under the default v4 stylesheet. Add a new element only after auditing the compiled v4 CSS for `>`, `+`, `~` and structural pseudo-class selectors of the component, and record the audit in the commit message.
- Undefined means unset. A decorator setter for a new input clears its explicit flag on `undefined` and falls back to the alias value or the default without warning: `this.nzNewExplicit = value !== undefined; this.resolved = value ?? this.aliasValue ?? DEFAULT;`. Signal inputs get this from `computed(() => nzNew() ?? nzOld())`.
- Sizes: where antd 6 renamed the default size to `medium`, type the input as `NzSizeDMSType` (`ng-zorro-antd/core/types`) and render `medium` exactly as `default`; `default` is not deprecated, so it gets no warning and no marker.
- Semantic slots: antd 6 `classNames`/`styles` props become `nzClassNames: NzSemanticClassNames<'root' | …>` and `nzStyles: NzSemanticStyles<'root' | …>` from `ng-zorro-antd/core/types`; `root` merges into the host bindings.
- A grid-style `flex` value goes through `parseFlex` from `ng-zorro-antd/core/util`, never a local copy.
- Render slots: an input that replaces an antd render callback (`itemRender`) is a `TemplateRef<Ctx>` where `Ctx.$implicit` is the default rendering as a `TemplateRef<void>` and the other fields mirror antd's callback arguments, so `[ngTemplateOutlet]="ctx.$implicit"` reproduces the default output. The context interface lives in the component's `typings.ts`; the convention is noted beside `NzSemanticClassNames` in `components/core/types/semantic.ts`.
- Data lists: a data input (`nzItems` on `nz-breadcrumb`, `nzTabList` on `nz-card`) renders the component's existing child element at the position projection uses, only while the input is bound; the v4 audit is then the one for that existing DOM. Mixing projection and data for one slot is unsupported and documented: Card lets the data list win and warns once (per app in dev mode, through the logger's dedupe), Breadcrumb lets `nzItems` win over `nzAutoGenerate` and warns once.
- Key over index: where a component gains a string key beside an existing index API (`nzActiveKey` beside `nzSelectedIndex` on `nz-tabs`), a bound key wins and binding both warns once per instance in dev mode (`warn` from `ng-zorro-antd/core/logger`); the index API keeps its current semantics, and with the key unbound the DOM output is byte-identical. Router mode, where a component has one, still takes precedence over keys and warns once when a key is bound with it. The convention is noted beside the render-slot note in `components/core/types/semantic.ts`.
- Controlled key: a bound `nz<Name>Key` input (`nzActiveKey`) is strictly controlled: a user pick emits the change output (`nzActiveKeyChange`) and the component shows the picked key only after the parent writes it back; with the key input unbound the pick shows at once and the `nzDefault<Name>Key` input seeds the internal value (an unknown default key falls back to the first item, as in antd). A bound key that matches no item shows nothing active and emits nothing. Programmatic key changes never emit. `nz-card` binds the Tabs keys for `nzTabList` instead of keeping its own key-to-index mapping.

### TypeScript Guidelines

- Use generics where appropriate to enhance type flexibility.
- Use intersection types (&) to combine multiple types.
- Use literal union types to define a limited set of options.
- Avoid using `enum` in favor of union types and `as const`.
- Rely on TypeScript's type inference whenever possible.
- Use type assertions (`as`) only when necessary.

### Responsiveness and Theming Support

- Components should display well on different screen sizes.
- All components must support dark mode.
- Components should support right-to-left (RTL) text directions.
- Use logical CSS properties (e.g., `margin-inline-start`) instead of directional properties (e.g., `margin-left`).
